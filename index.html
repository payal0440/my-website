What is web hosting?

Every website is a set of files: HTML, CSS, JavaScript, images, and sometimes a database. Those files must live on a computer that is always on and always connected to the internet. That computer is a server, and renting space on it is called web hosting.

  • A domain name is your address (example.com).
  • Hosting is the land and building where your site lives.
  • A browser is the visitor who knocks on the door.
  • Without hosting, nobody but you can see your website.

1. You upload files

Your HTML, CSS, JS and images are copied to the host through Git, FTP, or a dashboard.

2. A domain points to it

DNS records connect your domain name to the server’s IP address.

3. Servers answer requests

Software like Nginx or Apache sends the right file to each visitor over HTTP or HTTPS.

Why a CDN matters

A content delivery network keeps copies of your site on servers around the world. A visitor in Delhi gets files from a nearby city instead of waiting for a server in Virginia. Vercel, Netlify and Cloudflare include a CDN by default.

Deploy your first site

The quickest route is Git plus Vercel. No server setup, HTTPS included.

  • Put your project in a GitHub repository.
  • Open vercel.com/new and import the repo.
  • Keep the defaults for a static site and press Deploy.
  • Add your own domain under Settings → Domains.

Or use the command line

# install the Vercel CLI
npm i -g vercel

# inside your project folder
vercel login
vercel --prod

Check a site’s DNS

# see which IP a domain points to
nslookup example.com

Domain names & DNS

A domain is a human-friendly name. DNS is the phonebook that turns it into the server’s IP address. You manage it with a few record types.

A record

Points a domain to an IPv4 address, e.g. 76.76.21.21.

CNAME

Makes one name an alias of another, e.g. www → cname.vercel-dns.com.

MX record

Tells the world which server receives email for your domain.

TXT record

Stores text for ownership checks and email security (SPF, DKIM).

DNS changes can take from a few minutes up to 48 hours to spread. Buy domains from registrars such as Namecheap, Cloudflare or GoDaddy.

Security & performance

A good host does more than keep your site online. These are the features worth checking before you choose.

🔒 SSL / HTTPS

Encrypts data between visitor and server. Free via Let’s Encrypt on most hosts.

💾 Backups

Daily automatic copies let you restore the site after a mistake or attack.

🛡️ Firewall & DDoS shield

Blocks malicious traffic before it reaches your server. Cloudflare offers a free tier.

⚡ CDN

Serves files from a location near each visitor to cut load time.

🗜️ Caching & compression

Gzip or Brotli plus browser caching make repeat visits much faster.

📈 Uptime monitoring

Tools like UptimeRobot alert you when the site goes down.

Hosting glossary

Bandwidth
How much data your site can send to visitors per month.
Uptime
The share of time your site is reachable.
IP address
The numeric address of a server on the internet.
Nameserver
The server that holds your domain’s DNS records.
FTP / SFTP
Protocols for uploading files to a server.
cPanel
A popular control panel for managing shared hosting.
Serverless
Code that runs on demand without you managing a server.
Latency
The delay before data starts arriving after a request.

Frequently asked questions


Do I need to buy hosting and a domain separately?

Often yes. Some platforms give you a free subdomain such as yoursite.vercel.app. A custom domain is bought from a registrar like Namecheap or Cloudflare.

What is the difference between shared hosting and a VPS?

Shared hosting splits one server among many sites. A VPS gives you a dedicated slice of a server with more control and more responsibility.

Is free hosting good enough?

For portfolios, blogs and small projects, yes. Free plans usually limit bandwidth, build minutes, or commercial use, so read the terms.

What is SSL/HTTPS and do I need it?

HTTPS encrypts traffic between visitor and server. Browsers warn users about sites without it, and modern hosts add it automatically.

Can I move my site to another host later?

Yes. Copy your files and database, then update your DNS records. Plan a short overlap to avoid downtime.
